# Method Table Provenance

Use this skill to route Methods-facing provenance work for manuscript figures.
The top-level input contract is intentionally small, but a complete Methods
handoff has a named output contract so downstream manuscript components do not
need to reconstruct internal workflow state.

## Artifact Contract

Required artifact:

- A set of manuscript figures or panels with enough metadata to trace each panel
  back through its generating artifacts and transformations.

The metadata may be supplied as manifests, package provenance files, legends,
semantic notes, package inventories, scripts, configs, saved tables, or another
equivalent figure package. Do not require a specific file layout when the same
trace facts are available another way. If the required figure/panel + metadata
package cannot identify the requested panel or cannot support a trace through 
generating artifacts and transformations, report
the gap instead of inventing provenance.

Optional artifacts:

- User feedback, instructions, corrections, or scope constraints.
- Existing outputs generated by this skill.

## Canonical Methods Handoff Contract

When the requested output is a complete Methods-ready handoff, or involves
writing or revising methods text, write a canonical bundle under the user-specified output
root, or under a concise local root such as:

```text
<methods_root>/
  target_figure_set.tsv
  manuscript_endpoint_verification.md
  methods_text.md
  locked_provenance_table.md
  provenance_lock_verification.md
  node_classification.csv
  methods_spine.md
  final_methods_draft_audit.md
  methods_handoff.md
```

Files in the canonical bundle should be singular, and should fully reflect the
complete scope of the methods. 

Optional supporting artifacts may be preserved when generated, but they are not
the canonical consumer contract unless the user asks for process reproduction:

```text
<methods_root>/
  source_fact_cards/
  reviewer_points.md
  unresolved_methods_issues.md
```


## General policy

Downstream workflows require a current upstream provenance basis.

The canonical locked provenance deliverable is one current-snapshot graph. Its
structural leaves must be exactly the manuscript-visible panels declared in the
Methods-local target figure-set manifest, and every row must be upstream-
reachable from those leaves. Do not add a separate endpoint table.

For a revision, declare one row per manuscript-visible panel from the supplied
figure/panel artifact package in the endpoint verifier's target-manifest format.
This manifest is generated from the required figure/panel package; it is not an
additional upstream dependency.

For Methods spine or Methods drafting requests, do not automatically regenerate every upstream artifact. Use the minimum valid artifact chain needed for the requested output.

If no required upstream artifact exists, generate only the missing prerequisite artifacts needed for the requested task. If upstream artifacts already exist, first verify the locked provenance table against the declared target figure-set manifest when available. If the locked provenance table verifies against the current figure/panel scope, treat derived artifacts such as node classifications, Methods spines, and prior Methods drafts as reusable unless there is evidence that they are missing, stale, mismatched, or explicitly targeted by the user’s request.

IMPORTANT: If provenance-table verification fails, IMMEDIATELY repair or reconstruct the affected provenance, then propagate changes downstream only where the repaired provenance invalidates existing classifications, spine entries, or prose.

Do not invent provenance or Methods claims. Work only from supplied figure/panel artifacts, provenance files, tables, scripts, configs, manifests, legends, notes, or explicit user corrections. If trace support is missing, ambiguous, stale, or contradictory, report the gap instead of producing unsupported provenance or Methods text.

Subagents are mandatory for requests that genuinely require multiple workflow roles. The router owns scope control. Subagents should not independently expand the task, regenerate valid artifacts, or rewrite downstream outputs unless instructed. They should return only the artifact or check assigned to them.

When directly responding to user instructions or feedback, identify the coordinating role as `router`.

A typical router workflow is:

1. Read the user request, feedback, and scope constraints.
2. Identify the requested canonical output.
3. Identify the manuscript-visible panel endpoints in the supplied figure/panel
   package and materialize `target_figure_set.tsv`.
4. For a revision, verify that manifest against the structural leaves of the
   existing locked provenance table using `scripts/verify_manuscript_endpoints.py`.
5. Discover the relevant provenance artifacts and existing Methods outputs.
6. Determine the minimum prerequisite chain for the requested output.
7. Reuse existing downstream artifacts only when the endpoint and provenance
   checks pass.
8. Repair or generate only missing, invalid, or explicitly targeted artifacts.
9. Assemble and return the requested canonical Methods artifact.


## Workflow Routing

Read only the reference needed for the requested task:

- `references/provenance_table_construction.md`: workflow for building or
  merging the canonical locked provenance table.
- `references/provenance_table_verification.md`:  workflow for checking
  whether an existing locked provenance table still matches current artifacts
  and supplied manuscript figure/panel scope.
- `references/node_classification.md`: workflow for classifying nodes
  in an existing provenance table.
- `references/methods_spine.md`: workflow for building a bucket-scoped
  Methods outline from a classified provenance graph.
- `references/methods_drafting.md`: workflow for drafting Methods text
  from a Methods spine.

Do not draft manuscript prose unless the user requests Methods drafting or a
reference workflow explicitly calls for a drafting role.
