# Shared Figure Objects

## Purpose

This reference defines the shared object vocabulary for the manuscript figure
workflow. Workflow files should use this vocabulary rather than duplicating
object schemas locally.

The contract shape is:

- one master figure index object that carries final manuscript names,
  package/local aliases, current names, prior-draft correspondence, image paths,
  image hashes, and panel-level source/provenance fields;
- one rebuild object for rerun commands, promoted scripts, wrapper scripts, and
  dependency lists that would make the master index too wide or repetitive;
- one semantic interpretation artifact object;
- visual QC and validation outputs that check the preceding artifacts exist and
  agree.

## General Conventions

Each object below states its row grain. A table must not mix grains unless the
object definition explicitly permits it.

Path rules:

- All paths should be repository-root-relative.
- Use absolute paths only for artifacts outside the repository or on shared
  storage where no repository-relative path exists.
- Do not mix polishing-root-relative and integration-root-relative paths in the
  same handoff contract.

Scalar and list rules:

- Use `NA` for unavailable or not-applicable scalar fields in CSV/TSV outputs.
- Use semicolon-separated paths for multi-path cells.
- Store hashes as lowercase SHA256 hex strings.
- Keep source, regenerated, and final normalized image paths distinct.
- Do not use shared approval-bypass fields. Validation should instead report
  `PASS`, `WARN`, `FAIL`, or `BLOCKED`, with concise notes and explicit
  user-approval references when a warning is intentionally accepted.

## FigureIndexRow

Canonical master row for a manuscript-visible panel. This is the place where
figure naming, package aliases, current/final names, image hashes, panel source
fields, semantic interpretation paths, and prior-draft correspondence live.

Row grain:

- For subpaneled figures, create one row per manuscript-visible subpanel.
- For a single-panel figure with no subpanel letters, create one row with
  `panel_id = whole_figure`.
- Do not create an extra `whole_figure` row for a figure that already has
  subpanel rows. Whole-figure PNG paths and hashes are repeated on the subpanel
  rows for that figure.

Required identity and naming fields:

- `manuscript_figure_name`: final manuscript-facing figure name, such as
  `Figure 1` or `Figure S2`.
- `panel_id`: lowercase subpanel label, such as `a`, `b`, `c`, or
  `whole_figure`.
- `current_figure_name`: final normalized figure file stem or current canonical
  figure id used by the integrated package, such as `Figure_1` or `Figure_S2`.
- `source_local_figure_name`: package-local or polishing-local figure name from
  the source workflow.
- `intermediate_aliases`: semicolon-separated temporary, draft,
  continued-output, or package-local aliases not already captured by
  `source_local_figure_name`.
- `source_root`: repository-root-relative path to the polishing or source
  package root from which the panel was integrated.
- `prior_manuscript_figure_name`: prior draft manuscript figure name, or `NA`.
- `prior_panel_id`: prior draft panel id, or `NA`.

Required image and hash fields:

- `polishing_final_image_path`: polished final PNG from the source package, or
  `NA` before polishing exists.
- `polishing_final_sha256`: SHA256 of `polishing_final_image_path`, or `NA`.
- `integration_rebuild_image_path`: PNG regenerated from the promoted script in
  the integration target, or `NA` before integration rebuild exists.
- `integration_rebuild_sha256`: SHA256 of `integration_rebuild_image_path`, or
  `NA`.
- `final_image_path`: normalized final manuscript PNG containing the panel.
- `final_image_sha256`: SHA256 of `final_image_path`.
- `wrapper_rebuild_image_path`: PNG regenerated by the final wrapper script, or
  `NA` before wrapper validation exists.
- `wrapper_rebuild_sha256`: SHA256 of `wrapper_rebuild_image_path`, or `NA`.
- `hash_match_status`: `match`, `mismatch`, `not_run`, or `not_applicable`.

Required panel source fields:

- `source_script_path`: script or notebook that defines the panel content.
- `source_function_or_object`: function, object, report export, or plot builder
  when available.
- `data_input_paths`: direct plotted inputs.
- `configuration_paths`: style, thresholds, model summaries, or layout configs
  needed to interpret the panel.
- `subpanel_audit_image_path`: cropped or audit image path, or `NA`.

Required interpretation field:

- `semantic_interpretation_path`: path to the matching interpretation artifact.

Field ownership by workflow:

- Polishing supplies source-local names, source roots, panel labels, polished
  final image paths/hashes, source script paths, source object names, data
  inputs, configuration paths, and subpanel audit images when available.
  Polishing does not own final manuscript numbering.
- Figure-set integration owns final manuscript numbering, current normalized
  figure names, final image paths/hashes, integration rebuild paths/hashes,
  wrapper rebuild paths/hashes, hash-match status, and prior-draft
  correspondence fields.
- Semantic interpretation consumes the canonical index to determine targets and
  supplies or confirms `semantic_interpretation_path`.
- The main skill treats the integration-written index as the canonical figure
  handoff index.

`intermediate_aliases` examples:

- A draft package writes `figure_4_s8_candidateA.png`, polishing calls it
  `FG4S8_final.png`, and integration normalizes it to `Figure_S8.png`.
- A package-local script emits `posterior_summary.png`, but the final manuscript
  name is `Figure 3`.
- A continued output was called `Figure_2_revision_panelset` in a previous draft
  package but is now integrated as `Figure S4`.

`source_root` rationale:

- This field makes the master index sufficient to navigate back from a final
  panel to the package or polishing root that supplied it.
- It is consumed by source/provenance review, rebuild validation, and later
  methods provenance work.
- If a row was created entirely inside integration, use the integration root.

## RebuildRecord

Command-level contract for regenerating whole-figure images. This object exists
because full commands, promoted script paths, wrapper commands, and dependency
lists are too verbose to repeat across every subpanel row in the master figure
index.

Row grain:

- one row per command-output pair;
- if one wrapper command regenerates multiple final figures, repeat the command
  in one row per regenerated target figure.

Natural join keys:

- `manuscript_figure_name`
- `current_figure_name`
- `stage`

Required fields:

- `stage`: `polishing`, `integration`, `package_wrapper`, or
  `validation_rebuild`.
- `manuscript_figure_name`
- `current_figure_name`
- `source_root`: source package, polishing root, or integration root.
- `script_path`: stage-local script path.
- `working_directory`: directory from which the command must run.
- `command`: exact rerun command.
- `target_image_path`: final or source image being matched.
- `target_sha256`: expected SHA256 of `target_image_path`.
- `rebuild_output_path`: path actually produced by the command.
- `rebuild_sha256`: observed SHA256 of `rebuild_output_path`.
- `hash_match_status`: `match`, `mismatch`, `not_run`, or `not_applicable`.
- `direct_input_paths`: plotted or directly consumed data/config paths.
- `dependency_paths`: helper scripts, style files, layout plans, manifests,
  fixed configs, or promoted assets needed for reproducibility.
- `immutable_raster_inputs`: paths to approved raster inputs, or `NA`.

Field ownership by workflow:

- Polishing writes one `stage = polishing` row per polished whole-figure output.
  The command should regenerate the polished final PNG inside the polishing root.
- Figure-set integration writes one `stage = integration` row per promoted
  package script rerun inside the integration target. The regenerated PNG is
  compared to the corresponding polishing final PNG by SHA256.
- Figure-set integration or manuscript assembly writes `stage = package_wrapper`
  rows for wrapper-level commands that rerun the complete integrated figure set.
- Validation may write `stage = validation_rebuild` rows when it reruns commands
  in a clean or separate validation location.

R entrypoints should be invoked through `scripts/agentRrunner.sh`.

Immutable raster inputs are inputs that must be named and validated under the
global raster policy in `SKILL.md`.

## SemanticInterpretationArtifact

Manuscript-facing interpretation artifact for one rendered panel or single-panel
whole-figure target. Visual claims must remain based only on fresh-context
visual inspection.

File grain:

- one artifact per `FigureIndexRow`.

Required sections:

- `Target`: exact image path and supplied figure/panel label.
- `Fresh-Context Visual Description`: retained image-inspector output or a
  marked excerpt with path to full retained output.
- `Panel-Scoped Source Clarification`: clarification output or extract with
  visible-element resolution and source chain.
- `Visual Claims`: claim-led bullets supported only by fresh visual description.
- `Visual-Only Interpretation`: apparent message from pixels alone.
- `Clarification Notes`: source-clarification notes only.
- `Visual Caveats`: visible limitations and ambiguities.
- `Not Assessed`: explicit statement of excluded review scopes.

Do not use source clarification, external legends, filenames, paths, or prior
manuscript context as support for visual claims.

## VisualQCRecord

Structured validation detail for direct visual inspection of rendered PNGs.

Row grain:

- one row per inspected final, rebuilt, or subpanel-audit image path.

Required fields:

- `image_path`
- `manuscript_figure_name`
- `panel_id`: panel label, `whole_figure`, or `NA` for multi-panel whole-figure
  images.
- `inspection_scope`: `draft`, `polishing_final`, `integration_final`,
  `handoff_final`, or `subpanel_audit`.
- `no_title_caption_header`: `pass`, `fail`, or `not_checked`.
- `clipping`: `pass`, `fail`, or `not_checked`.
- `spacing_layout`: `pass`, `fail`, or `not_checked`.
- `readability`: `pass`, `fail`, or `not_checked`.
- `panel_order_labels`: `pass`, `fail`, or `not_checked`.
- `density_or_caveats`
- `status`: `pass`, `fail`, or `not_checked`.
- `notes`

Visual QC must be based on inspecting the image, not only file existence,
dimensions, hashes, or command logs.

## ValidationSummary

Machine-readable validation output for the shared contract. Validation should
answer whether the final figure set is complete and internally consistent.

File grain:

- one validation summary per workflow stage or final handoff package.

Required fields:

- `status`: `PASS`, `WARN`, `FAIL`, or `BLOCKED`.
- `checked_figure_index_rows`
- `checked_final_images`
- `checked_rebuild_records`
- `checked_semantic_interpretations`
- `checked_visual_qc_records`
- `errors`: list or semicolon-separated values.
- `warnings`: list or semicolon-separated values.
- `ok`: list or semicolon-separated values.
- `approval_references`: user instruction, plan path, notes path, or `NA` for
  accepted warnings.

Minimum final-handoff validation checks:

- every `FigureIndexRow` has a `final_image_path` and `final_image_sha256`;
- duplicated figure-level fields in `FigureIndexRow` are identical across rows
  with the same `manuscript_figure_name`;
- every final manuscript figure has at least one matching `RebuildRecord`;
- rebuild hashes match the corresponding source or final image hashes unless
  the mismatch is reported as `FAIL` or explicitly downgraded to `WARN` with an
  approval reference;
- every manuscript-visible panel has source fields sufficient to identify the
  plotted inputs or a blocking validation error;
- every manuscript-visible panel has a semantic interpretation path;
- every final image has a visual QC record.
