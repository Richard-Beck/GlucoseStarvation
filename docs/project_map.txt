• Current end-to-end path

  1. Raw images and object-level classification
     Counts path starts by linking raw images with workflow/preliminaries_and_metadata.Rmd:19 via scripts/mapFolders.R,
     then parsing filename metadata with get_meta() in scripts/define_plate_maps.R:105. Object classification is
     produced by process_image_key() / process_well_id() / main() in scripts/image_processing/
     batch_segment_and_classify.py:62, which depend on build_raw_group_map, make_cpose_input, and make_composite.
  2. Count aggregation and optional count smoothing
     workflow/adaptive_cell_count.Rmd:60 aggregates batch object results into data/counts/uncorrected.Rds. It optionally
     runs optimize_counts() in src/optimize_counts.R:2, which calls preprocess_dt() and calculate_total_cost() in src/
     count_smoothing.cpp, then writes data/counts/corrected.Rds at workflow/adaptive_cell_count.Rmd:156.
  3. Stan data construction
     The actual Stan input is built only by R/prepare_data.R. Key functions are as_corrected_counts() at line 39,
     get_grid_idx() at line 221, and costf() at line 291. This script reads data/counts/uncorrected.Rds at R/
     prepare_data.R:72, merges glucose calibration/data CSVs, constructs the stan_data list at R/prepare_data.R:333, and
     saves data/stan_ready_data.Rds at R/prepare_data.R:388.
  4. Model configuration, compilation, optimization, sampling
     The active model family is gpath and has now been versioned outside ecology. The current code version is
     models/gpath/v1/model.R plus models/gpath/v1/gpath_hier.stan. Core helpers are parse_run_id(),
     get_hierarchical_k(), generate_stan_config(), get_param_names(), and reconstruct_parms().

     The current versioned optimisation pipeline is pipelines/gpath/optim/run_start.R plus
     pipelines/gpath/optim/combine.R. It loads stan_ready_data via R/gpath_run_utils.R, compiles the versioned Stan
     file, runs per-start optimisation, and writes outputs plus a run_manifest.json under
     data/runs/gpath/v1/optim/<dataset>/<run_id>/<run_label>/.
     The canonical assessment set of `gpath` model IDs now lives at models/gpath/v1/assessment_run_ids.txt; the
     spec generator scripts/make_gpath_optim_spec.R can read that file directly when constructing batch rerun specs.

     Older legacy optimisation/NUTS code still exists under ecology/model_selection/models/gpath/, but that is now a
     reference path rather than the intended home for active development.

     Pathfinder is ecology/model_selection/models/gpath/pathfinder.R: same data/config path, compile at line 71, run
     mod$pathfinder() at line 174, save outputs at lines 194-198.

     Legacy CV NUTS is ecology/model_selection/models/gpath/nuts_cv.R, which rebuilds is_train by holding out the
     max-ploidy wells for one cell line, then samples one chain per fold/chain combination.

     The newer directional transfer CV path lives outside ecology: R/gpath_run_utils.R now has
     get_directional_transfer_split() / apply_directional_transfer_holdout(), scripts/run_gpath_transfer_cv.R runs
     null/transfer/oracle multi-start optimizations for low->high or high->low line-transfer evaluation using the
     existing gpath_hier.stan, with selectable init modes (`auto`, `posterior`, `random`) and optional
     `ploidy_effect_mask` restriction so only selected ploidy coefficients are active, and
     scripts/summarize_gpath_transfer_cv.R picks the best start per condition before aggregating transfer-gain /
     transfer-regret summaries. Parameter-level transfer analysis now lives in R/parameter_transfer_utils.R and
     scripts/summarize_gpath_parameter_transfer.R, which reconstruct held-out-line mechanistic parameters for the best
     transfer and oracle fits and compare the inferred missing-state parameter values and ploidy-induced shifts.
     Visualization helpers for this parameter-transfer output now live in R/parameter_transfer_plot_utils.R and
     scripts/plot_gpath_parameter_transfer.R.
     Single-parameter transfer screening specs can now be generated with scripts/make_gpath_single_param_transfer_spec.R,
     which writes one masked transfer-screen row per model parameter and directs outputs into separate roots under
     data/gpath_transfer_cv_single_param/. Aggregated reporting for those masked screens now lives in
     scripts/report_gpath_single_param_screen.R, which scans the per-mask roots and writes screen-level CSV/PNG
     summaries under data/gpath_transfer_cv_single_param/report/.
     There is now a parallel NUTS version of the same workflow: scripts/run_gpath_transfer_nuts.R,
     scripts/summarize_gpath_transfer_nuts.R, and slurm/submit_gpath_transfer_nuts_pipeline.sh write under
     data/gpath_transfer_cv_nuts/.
  5. Model comparison, diagnostics, plots/tables
     The main comparison notebook is workflow/model_analysis.Rmd. It is now intended as a reporting notebook rather than
     a scratchpad: it documents upstream commands, reads saved outputs from the current `gpath` workflow, reports model
     ranking / optimisation stability, presents directional transfer summaries, and loads parameter-transfer summaries
     and plots generated by the newer helper scripts under R/ and scripts/.

     There is also a plotting helper script, ecology/model_selection/models/gpath/plot_fits.R, with
     generate_line_data(), plot_line_trajectories(), and prep_line_diag_exact() for simulated-vs-observed fit plots.
     Transfer-CV plotting now lives in R/transfer_cv_plot_utils.R and scripts/plot_gpath_transfer_cv.R, which load the
     best optimization start per null/transfer/oracle condition, simulate the held-out line, and overlay fits with
     color by fit type and linetype by transfer direction. Batch export of annotated transfer overlays now lives in
     scripts/export_gpath_transfer_overlays.R, which writes per-model/per-line PNGs plus a manifest under
     data/gpath_transfer_cv_overlays/.

     Cluster submission is beginning to move outside ecology. slurm/README.md defines the target structure:
     `slurm/jobs/` for stable job scripts, `slurm/submit_*.sh` for one-shot wrappers, and `slurm/runs/...` for generated
     manifests/job metadata. The directional transfer workflows currently use this new path via
     slurm/submit_gpath_transfer_pipeline.sh and slurm/submit_gpath_transfer_nuts_pipeline.sh plus their
     corresponding `slurm/jobs/gpath_transfer*.sh` job scripts. These submit wrappers now clear `slurm/logs/` before a
     new batch submission to keep log volume manageable. There is now also a batch screening wrapper for optimization
     transfer, driven by scripts/make_gpath_transfer_screen_spec.R and
     slurm/submit_gpath_transfer_screen_pipeline.sh, intended for random-init screening across the canonical assessment
     model set without any NUTS dependence. A ready-to-use assessment screening spec now lives at
     data/specs/gpath_transfer_screen_assessment.tsv.
     The versioned optimisation rerun path is now spec-driven: generate a TSV with
     scripts/make_gpath_optim_spec.R, submit it with slurm/submit_gpath_optim_pipeline.sh, and the job layer uses
     slurm/jobs/gpath_optim_{array,combine}.sh. Each run writes under data/runs/... and includes a run_manifest.json;
     scripts/verify_gpath_run_manifest.R compares that manifest against the current Stan/data/script files. Aborted
     optimisation batches can be cleaned by batch label with scripts/cleanup_gpath_optim_batch.R. The combine job now
     uses an `afterany` dependency on the optimisation array so partially successful runs still produce combined outputs.
