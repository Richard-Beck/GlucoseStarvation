• Project aim

  The scientific aim is to determine how ploidy changes cancer cell behavior under glucose limitation, and whether
  those ploidy-associated changes are generalizable enough across cell lines to support strategies that select for or
  against high-ploidy states, including in potentially unseen lines. Directional transfer workflows in this repo are
  used as stress tests of cross-line generalizability toward that aim, not as an end goal on their own.

  Model-free ploidy-summary branch

  This branch uses the same `stan_ready_data` object but does not fit the ODE. R/model_free_ploidy_utils.R reconstructs
  count/glucose trajectories per well from `stan_ready_data`, converts glucose luminescence to estimated glucose using
  the stored calibration parameters, and derives per-condition summary features such as peak live counts, alive/dead
  AUCs, max(total) yield, growth/death slopes, glucose drawdown, and timing metrics.

  scripts/extract_model_free_ploidy_features.R writes those derived tables under data/model_free_ploidy/ including
  feature_panel.Rds/CSV plus a second-layer signature_panel.Rds/CSV. That signature layer aggregates across initial
  glucose with feature-specific rules and is now intentionally reduced to a curated 8-feature panel: low/high-glucose
  medians for max growth and max death, intercept/slope from alive-AUC vs log1p(G0), and intercept/slope from a crude
  peak-yield metric defined as max(live+dead) up to the final glucose measurement divided by glucose drawdown.
  Growth/death maxima are now extracted from gently smoothed well trajectories, while the reporting notebook also shows
  less-processed trajectory views and raw-versus-smoothed condition summaries so the feature construction is easier to
  audit. Initial glucose is displayed in the notebook as evenly spaced categorical levels rather than on a pseudo-log
  continuous axis.
  Paired ploidy-effect summaries are computed on these aggregated signatures. scripts/evaluate_model_free_ploidy_transfer.R
  then performs a leave-one-line directional transfer benchmark on the curated signature panel, using the median
  cross-line ploidy effect per signature as the transferred effect and reporting scaled error summaries so
  heterogeneous feature magnitudes do not dominate. The same script now also writes a simple outlier-robustness sidecar:
  robust per-line discordance scores in signature-effect space plus leave-one-training-line influence summaries for the
  remaining holdout lines, so any proposed line exclusion is auditable rather than ad hoc. Here again, the transfer
  benchmark is mainly a check on whether the observed ploidy signatures are stable enough across lines to support
  broader selection-oriented hypotheses.
  workflow/model_free_ploidy_analysis.Rmd is the reporting notebook for this branch and now presents one section per
  curated feature with rationale plus the corresponding computation plot, and now includes an explicit outlier-robustness
  section; it also writes workflow/model_free_ploidy_analysis.txt as an agent-readable results companion.
  workflow/transfer_spline_first_attempt.Rmd is a separate exploratory notebook that rebuilds observed total-cell and
  estimated-glucose trajectories from `stan_ready_data`, fits conservative positive smooth splines per
  cellLine/ploidy/G0 panel, derives empirical rate-vs-glucose relationships after dropping any well with censored
  glucose, and screens reduced residual models to ask which extra state summaries (density, time, lagged or integrated
  history, well effects) tighten those relationships. The notebook frames those findings mainly as support for hidden
  state in general, with the active `gpath` resource/waste states as plausible carriers of the slow structure, rather
  than as a direct critique of the mechanistic workflow.
  scripts/explore_transfer_spline_integrated_state.R is a targeted follow-up screen that keeps the same spline-derived
  uncensored rate table but expands single-covariate residual-structure comparisons (including isolated integrated-history
  candidates) and writes CSV summaries under data/report_exports/transfer_spline_integrated_state/.

  Selection-strategy simulation branch

  This branch uses fitted `gpath` parameters directly rather than feature engineering. R/selection_strategy_utils.R
  reconstructs low- and high-ploidy parameter sets for one cell line, combines them into a shared-media mixed-culture
  ODE via `rhs_mix`, seeds the mixture at 50:50 high:low with total live count reset to the fitted mean of the two
  state-specific `N0` estimates, and simulates fixed 6-day strategies built from the observed 7 glucose conditions with
  optional day-2/day-4 media refresh. Refresh resets glucose / auxiliary resources / waste and rescales total live
  count back to that fitted starting density while preserving the current high-ploidy fraction.

  scripts/run_gpath_selection_strategy_batch.R is the top-level named-argument wrapper for batch simulation across
  available global and transfer fits; it reads defaults from scripts/selection_strategy_config.R and writes per-task
  `interval_summary.Rds`, `final_summary.Rds`, optional `detail.Rds`, and `task_meta.Rds` under
  data/selection_strategy/gpath/v1/<dataset>/... . workflow/selection_strategy_analysis.Rmd is the reporting notebook;
  it aggregates those outputs, applies basic ranking criteria for selecting for or against high ploidy, and reruns a
  small number of top strategies in detailed mode for trajectory plots. The notebook now also contains a SUM-159
  competition-validation section that maps `data/counts/competition/SUM-159-fuse.Rds` onto the mixed-culture state
  variables and treats each frame as 8 hours. The original existing-fit context comparison remains in place, and there
  is now a supplementary single-line model-check section that scores the best completed line-5 fit for each model from
  `data/runs/gpath/v1/optim/gstarvation_v1_single_line/...` against empirical composition/live-burden trajectories,
  writing sidecars under `data/selection_strategy/gpath/v1/gstarvation_v1_single_line_competition_validation/`.
  Those helpers live in R/selection_strategy_utils.R as prepare/evaluate/score competition-validation utilities.
  scripts/render_gpath_selection_strategy_report.R renders that notebook without requiring positional
  arguments. Cluster execution now follows the standard manifest
  pattern via scripts/make_gpath_selection_strategy_manifest.R, slurm/jobs/gpath_selection_strategy_array.sh, and
  slurm/submit_gpath_selection_strategy_pipeline.sh.

  Competition-validation side branch

  data/counts/competition/ currently holds empirical mixed-culture count tables that are not part of the Stan training
  path. workflow/competition_analysis.Rmd is the lightweight report for this branch: it audits the object structure,
