• Project aim

  The scientific aim is to determine how ploidy changes cancer cell behavior under glucose limitation, and whether
  those ploidy-associated changes are robust enough across cell lines to support broader mechanistic interpretation and,
  only if warranted later, selection-oriented hypotheses. The map below distinguishes the canonical pipeline from a few
  remaining side paths that are scientifically useful but not part of the default mechanistic path.

• Current repo state

  A large legacy cleanup removed the older ecology tree, the transfer-CV workflow family, the old `*_old` image-training/
  eval branches, and the deprecated single-condition / deprecated-report notebooks. Some helper files and saved Slurm run
  records still contain transfer-oriented path strings; treat those as dangling historical references unless they are
  wired back into a maintained workflow.

• Core / canonical pipeline

  1. Raw images to object-level classifications
     The counts path starts by linking raw images with workflow/preliminaries_and_metadata.Rmd via scripts/mapFolders.R,
     then parsing filename metadata with get_meta() in scripts/define_plate_maps.R. Object classification is produced by
     scripts/image_processing/batch_segment_and_classify.py and its helper functions.
  2. Count aggregation and optional smoothing
     workflow/adaptive_cell_count.Rmd aggregates batch object results into data/counts/uncorrected.Rds. It can also run
     optimize_counts() in src/optimize_counts.R, which calls the C++ smoothing code in src/count_smoothing.cpp and writes
     data/counts/corrected.Rds.
  3. Canonical Stan-data build
     The base Stan input is built by R/prepare_data.R. It reads the count tables, merges glucose calibration/data CSVs,
     aligns the alive-cell area quantile sidecar from data/counts/batch_results_TEMP_MEASURE_SIZE.csv, and writes
     data/stan_ready_data.Rds plus data/stan_ready_data_with_area.Rds. Treat this script as the canonical builder for the
     full-data mechanistic input object; derived/subset Stan-data objects may be created elsewhere for special workflows.
  4. Versioned gpath optimization
     The active mechanistic model family is models/gpath/v1/model.R plus models/gpath/v1/gpath_hier.stan. The canonical
     optimization path is pipelines/gpath/optim/run_start.R plus pipelines/gpath/optim/combine.R, which load stan_ready_data
     via R/gpath_run_utils.R, run multi-start optimization, and write run directories plus run_manifest.json under
     data/runs/gpath/v1/optim/<dataset>/<run_id>/<run_label>/. The assessment model set lives at
     models/gpath/v1/assessment_run_ids.txt. Locked reruns use the reproducibility directories plus sha256 helpers in
     R/validation_utils.R.
  5. Canonical full-data NUTS
     The current full-data sampling path is driven by config/jobs/gpath_full_oracle_assessment.json, scripts/prepare_jobs.R,
     scripts/run_job.R, R/job_config_utils.R, and R/nuts_utils.R. Submission goes through
     slurm/submit_gpath_full_oracle_job.sh and slurm/jobs/gpath_full_oracle_array.sh. This is the current maintained NUTS
     path for oracle/full-data posterior checks.
  6. Canonical reporting
     workflow/model_analysis.Rmd is the main reporting notebook for the current mechanistic path. It reads saved optimization
     summaries, reports model-selection diagnostics, checks the current oracle-NUTS outputs, visualizes reconstructed
     line/ploidy parameter structure, and summarizes held-out-condition predictive/parameter comparisons from the saved
     optimization summaries. It is a reporting notebook with some cache regeneration, not a full rebuild of every upstream
     artifact. Notebook-specific helpers live in R/model_analysis_utils.R.

• Exploratory / hypothesis-generating branches

  1. Model-free ploidy summaries
     This branch uses the same stan_ready_data object but does not fit the ODE. R/model_free_ploidy_utils.R reconstructs
     count/glucose trajectories per well, derives summary features, and scripts/extract_model_free_ploidy_features.R writes
     feature and signature panels under data/model_free_ploidy/. scripts/evaluate_model_free_ploidy_transfer.R performs a
     holdout-line transfer benchmark on those signatures as a robustness check on observed ploidy summaries. The reporting
     notebook is workflow/model_free_ploidy_analysis.Rmd, which also writes workflow/model_free_ploidy_analysis.txt.
  2. Spline / hidden-state exploration
     workflow/transfer_spline_first_attempt.Rmd rebuilds observed trajectories from stan_ready_data, fits smooth empirical
     rate-vs-glucose relationships, and asks which extra state summaries reduce residual structure. scripts/
     explore_transfer_spline_integrated_state.R is a follow-up screen that writes CSV summaries under
     data/report_exports/transfer_spline_integrated_state/. This branch is exploratory support for hidden-state reasoning,
     not part of the canonical mechanistic workflow.
  3. Area / morphology side path
     The area-aware sidecar built in R/prepare_data.R writes data/stan_ready_data_with_area.Rds. workflow/area_quantile_eda.Rmd
     is the lightweight reporting notebook for that object. This makes morphology available for exploratory analysis, but it
     is not yet a first-class downstream fitting branch.
  4. Selection-strategy simulation
     This branch uses fitted gpath parameters rather than feature engineering. R/selection_strategy_utils.R builds a
     mixed-culture simulation ODE, scripts/run_gpath_selection_strategy_batch.R writes batch outputs under
     data/selection_strategy/gpath/v1/<dataset>/..., and workflow/selection_strategy_analysis.Rmd reports those results.
     Treat this as a downstream hypothesis-generation branch built on mechanistic fits, not part of the canonical fitting
     pipeline itself.

  Competition-validation side branch

  data/counts/competition/ currently holds empirical mixed-culture count tables that are not part of the Stan training
  path. workflow/competition_analysis.Rmd is the lightweight report for this branch: it audits the object structure,
  reconstructs 2N/4N/dead competition summaries such as `frac_4N`, `log(4N/2N)`, total-live, and dead-fraction
  trajectories, and frames those summaries as validation targets for the mixed-culture selection-strategy simulations
  rather than as model-fitting input.

  Image-derived feature branch

  This is separate from the Stan path. The size-aware classifier is scripts/image_processing/
  batch_segment_and_classify_TEMP_MEASURE_SIZE.py, which adds cell_size_px. workflow/preliminaries_and_metadata.Rmd:65
  reads batch_results_TEMP_MEASURE_SIZE.csv, builds data/counts/uncorrected_features.Rds at line 87, and uses that for
  exploratory feature plots. That feature table is still not consumed by R/prepare_data.R or the Stan fitting scripts,
  so the original image-derived branch remains exploratory rather than a first-class modelling path. The current live
  extension is an area-aware sidecar in R/prepare_data.R:
  it aligns alive-cell size quantiles from batch_results_TEMP_MEASURE_SIZE.csv to the count-observation rows and writes
  data/stan_ready_data_with_area.Rds. workflow/area_quantile_eda.Rmd is the new lightweight reporting notebook for that
  object: it plots q50/q99/tail-ratio trajectories, derives a crowding-adjusted latent volume proxy from the central
  area quantiles, shows within-line ploidy contrasts, morphology-versus-glucose relationships, and a cleaned-up port of
  the size-to-glucose-cost scaling idea from workflow/volume_aware_anal.Rmd. Current status: morphology is now
  available as an auxiliary analysis dataset, but only through this area-quantile side path; there is still no
  downstream fitting or transfer workflow that treats the broader image-derived feature panel as a primary branch.
  A newer bootstrap path is scripts/image_processing/batch_extract_object_features.py plus
  scripts/image_processing/run_batch_object_features.sbatch: it runs Cellpose without the classifier layer, derives
  per-object `area_px`, `live_mean`, `dead_mean`, `live_bg_z`, and `dead_bg_z` from the normalized composite channels,
  and writes each run into a timestamped folder with the invocation and script copy saved alongside the CSV.
  Preliminary live/dead counts from that object-level output now run through
  scripts/image_processing/make_prelim_counts_from_object_features.R, which computes a global
  median-area cutoff (`area_px >= 0.05 * median(area_px)`), labels kept objects by sign of `live_bg_z - dead_bg_z`,
  parses `image_key` metadata with `get_meta()` from scripts/define_plate_maps.R, writes per-image counts plus
  condition columns (`prelim_counts_by_image.csv`), and saves commit/checksum provenance in
  `prelim_counts_meta.json` under the same run folder.
  A single-image annotation mockup helper now lives at
  scripts/image_processing/make_sample_annotation_preview.py: it builds an RGB composite for one `image_key`,
  extracts a 400x400 context crop, and overlays the central 200x200 annotation target box.
  Batch annotation-set construction now lives at scripts/image_processing/build_annotation_stack_90.py:
  it reads prelim_counts_by_image.csv, excludes `MCF10A-ctrl`/`MCF10A-hras`, selects one image per
  `cellLine x ploidy x glucose_bin(low/mid/high) x time_bin(early/mid/late)` stratum (90 total), and writes a
  single 16-bit ImageJ stack (`annotation_stack_90.tif`, axes `TCYX`) plus a per-frame manifest/metadata sidecar.
  Post-annotation object-dataset construction now lives at
  scripts/image_processing/build_object_dataset_and_embeddings.py: it runs batched Cellpose on the annotation stack,
  writes per-frame label masks (`0` background, `1..N` object ids), maps point annotations to object ids for binary
  `alive`/`not_alive` labels, excludes boundary-touching objects by default, and exports concatenated
  frame-embedding + masked-object-embedding + `log(area)` feature tables for classifier training.
  Cluster execution wrapper for that step now lives at
  scripts/image_processing/run_build_object_dataset_and_embeddings.sbatch (activates `cpose` and writes
  labels/feature-table outputs into the chosen run folder).
  A simple downstream training/reporting path now lives at
  scripts/image_processing/train_object_embedding_classifier.py,
  scripts/image_processing/plot_object_embedding_classifier_results.R, and
  scripts/image_processing/run_train_object_embedding_classifier.sbatch: the trainer fits a standardized logistic
  regression on `log_area_px + obj_emb_* + frame_emb_*` with `label_int` as the target and saves metrics/predictions/
  coefficients/model bundle, the R script turns those saved artifacts into a compact PNG/TXT summary, and the sbatch
  wrapper runs both steps in the `cpose` environment.

  Agent-sidecar utilities

  agent-dev/ is a local handoff folder for agent reruns. It now contains a localized `1R_1P_0W_C0_M0` sidecar:
  agent-dev/gpath_hier.stan is a fixed-dimension specialization of the gpath hierarchy for one resource / one pathway /
  no waste, agent-dev/minimal_model_utils.R rebuilds the reduced Stan data directly from data/stan_ready_data.Rds plus
  the manifest-backed best-fit parameter row, agent-dev/run_log_lik.R recompiles that copy and prints the
  corresponding `best_lp` and `log_lik`, and agent-dev/run_optimize.R performs graceful hybrid-random multistart BFGS
  optimization against the simplified model while reporting hit rates relative to the canonical `log_lik`. The
  parameter source is still the canonical `1R_1P_0W_C0_M1` optimization output because `M` is irrelevant when `W=0`.
  agent-dev/task_1/ is now a small model-sweep sandbox around alternative reduced ODEs: task1_model_specs.R holds the
  generator/spec definitions, run_task1_model7_stabilization.R records stabilization attempts for the switching-P/Q
  variant, run_task1_directional_transfer.R runs directional low->high and high->low holdouts for all eight task-1
  models using split-clean random-prior starts, now refits both the original ploidy-aware form and a matched
  `null_ploidy` version with `ploidy_metric` zeroed on the same splits, and ranks split representatives by training fit
  before reading out held-out likelihood; summarize_task1_directional_transfer.R recomputes the aggregate ranking plus
  per-model gain-versus-null summaries from the saved per-split outputs, summarize_task1_parameter_transfer.R adds a
  parameter-view sidecar by comparing the transferred `ae`/`ah`/`Y_core`/`m` values against each model's full-data best
  fit, plot_task1_directional_transfer_summary.R adds a delta-vs-null plot, plot_task1_per_cell_line_fits.R writes
  per-line live/glucose fit panels under agent-dev/task_1/line_fit_plots/, and task1_report.Rmd reports the in-sample
  sweep, stabilization outcomes, and transfer/null comparison results from agent-dev/task_1/results/. Current status:
  these reduced-model transfer results look promising enough that the strongest task-1 candidates may be worth
  upgrading into the main workflow for a stricter apples-to-apples comparison against the existing `gpath` assessment
  set.
